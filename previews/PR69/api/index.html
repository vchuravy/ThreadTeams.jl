API

Everything that OhMyThreads.jl exports (tforeach, tmapreduce, treduce, tmap, tmap!, tcollect, @tasks, @set, @local, @task_index, @allow_boxed_captures, chunks, index_chunks, the other schedulers, ...) is re-exported; see the OhMyThreads.jl documentation.

Schedulers

ThreadTeams.TeamScheduler — Type
TeamScheduler(; busy = :tasks)

OhMyThreads.jl scheduler (also scheduler = :team) that runs a parallel operation on the worker pool: one contiguous chunk per thread of the :default pool, chunk 1 on the calling task and chunk c on worker c. The calling task also runs every chunk whose worker has not picked it up in time (asleep, or not scheduled by the OS), so a loop never waits for an idle worker. Lowest overhead; best for balanced iterations.

Only one parallel operation runs on the pool at a time. One started inside a chunk (nested) runs serially. One started while another task uses the pool runs on Threads.@spawned tasks with busy = :tasks (the default), and serially on the calling task with busy = :serial, which also runs the operation serially while a Threads.@threads loop runs (in any task: the check is process-wide). Use :serial in code that is itself run in parallel by tasks or @threads: spreading its loops over threads that are busy already only oversubscribes them. Chunks run in the caller's dynamic scope (ScopedValues, logger) and world age. If chunks throw, the exception of the first failing chunk is rethrown once all started chunks have finished.

The task index (OhMyThreads.WithTaskIndex, @task_index) is the chunk index; for chunks/index_chunks inputs the position of the chunk, as with the other schedulers. Task-local values (@local) live in the persistent worker tasks: initialized once per worker, reused across loops.

ntasks is not supported: chunks are not guaranteed to run at the same time, so @barrier can not be used.

ThreadTeams.GreedyTeamScheduler — Type
GreedyTeamScheduler(; nchunks = 0, chunksize = 0, busy = :tasks)

OhMyThreads.jl scheduler (also scheduler = :greedyteam) that runs a parallel operation on the worker pool with load balancing: nchunks contiguous chunks (default 4 * nworkers()), or chunks of chunksize elements. The calling task and the workers start with one chunk each, placed as with TeamScheduler, then take the others from a shared counter until none are left. For loops whose iterations take very different times. See TeamScheduler for the semantics both share.

Chunks are contiguous and reductions combine the chunk results in chunk order, so the operator only has to be associative and the result is deterministic for a given number of chunks. The task index is the chunk index.

The team

ThreadTeams — Module
ThreadTeams

A pool of persistent ("parked") worker tasks that runs OhMyThreads.jl's parallel functions (tforeach, tmapreduce, tmap, @tasks, ...) with low per-loop overhead. The package re-exports the OhMyThreads.jl API and adds two schedulers:

  • TeamScheduler (scheduler = :team): one contiguous chunk per thread of the :default thread pool, chunk 1 on the calling task, the others on the workers;
  • GreedyTeamScheduler (scheduler = :greedyteam): more chunks than threads, taken by the caller and the workers as they become free (load balancing).

One sticky worker task runs per thread of the :default thread pool. After its chunk, an idle worker spins for a short while (see ThreadTeams.set_spin_time!) before they sleep, so back-to-back loops pay for no task creation, scheduling or wake-up.

Pool controls: ThreadTeams.nworkers, ThreadTeams.set_spin_time!, ThreadTeams.spin_time, ThreadTeams.parallel_phase, ThreadTeams.shutdown!.

With Enzyme.jl loaded, parallel operations on the team can be differentiated in forward and reverse mode (a package extension; see the README).

ThreadTeams.nchunks — Function
ThreadTeams.nchunks(itr, scheduler = TeamScheduler()) -> Int

Number of chunks a parallel operation over itr would be split into right now: with the TeamScheduler at most one per thread of the :default thread pool, with the GreedyTeamScheduler as many as it asks for, and at most one per element. 1 means the operation runs serially: with a single thread, inside another parallel operation on the pool, and with busy = :serial while the pool is busy. (Loops also run serially during precompilation and, with busy = :serial, inside Threads.@threads, but that is decided later.)

ThreadTeams.foreach_chunk — Function
ThreadTeams.foreach_chunk(f, m::Int, p::Int = ThreadTeams.nworkers())

Call f(c) for every c in 1:m, each once, on at most min(p, m, nworkers()) threads at a time, the calling task being one of them. With as many chunks as threads, chunk c goes to the c-th participant (as with TeamScheduler); with more, participant c starts with chunk c, then the participants take the others from a shared counter until none are left (as with GreedyTeamScheduler). f decides what a chunk is, e.g. the iterations (c - 1) * n ÷ m + 1:c * n ÷ m of a loop of n.

Runs every chunk serially on the calling task, in order, when the team is busy (held by another task), when the call is nested in a team loop, while a Threads.@threads loop runs, during precompilation, and when m ≤ 1 or p == 1: never on spawned tasks (like busy = :serial).

Chunks that run at the same time never share a thread; a chunk runs on one thread unless it yields. Chunks run in the caller's dynamic scope and world age. If chunks throw, the exception of the lowest failing chunk is rethrown once the chunks already started have finished: every chunk before it runs, and the counter hands out no chunk after the failure is noticed.

The region code is compiled once per type of f. For a concrete type S, precompile(ThreadTeams.foreach_chunk, (S, Int, Int)) compiles all of it but the body of the workers' closure, which the first loop compiles when it creates the closure (a few milliseconds per type, against a few hundred without the statement).

ThreadTeams.set_spin_time! — Function
ThreadTeams.set_spin_time!(seconds::Real)

Set how long an idle worker busy-waits for the next parallel loop before it sleeps; default 100e-6 (100 µs). The time counts from the end of the worker's own chunk: a worker that finished early sleeps while a long chunk of another worker still runs, and one that the loops do not use sleeps even while loops run back to back. Takes effect the next time a worker starts waiting.

Longer spinning makes loops that follow each other with short serial gaps cheaper (waking a sleeping worker costs about 10 µs), but idle workers keep their CPU busy for that long after every chunk. With 0, workers sleep after 64 spins (about 100 ns; lowest CPU use, highest latency). To spin only during a part of the program, use ThreadTeams.parallel_phase.

On CPUs with performance and efficiency cores (recent Intel, Apple silicon), spinning cores take power and turbo headroom from the busy ones; LLVM's and GCC's OpenMP runtimes do not spin there by default. Consider set_spin_time!(0).

ThreadTeams.parallel_phase — Function
ThreadTeams.parallel_phase(f)

Call f() and return its result. While f runs, idle workers keep spinning instead of sleeping after spin_time(), and sleeping workers are woken at the start. Use it around a part of the program with many parallel loops separated by serial work longer than the spin time, so that the loops do not pay for waking the workers (about 10 µs each). Idle workers still sleep when their thread has another task to run, but otherwise keep their CPU busy until f returns.

Phases may be nested and may be active in several tasks at once.

ThreadTeams.parallel_phase() do
    for step in 1:nsteps
        serial_part!(state)       # e.g. 1 ms
        tforeach(eachindex(u); scheduler = TeamScheduler()) do i
            ...
        end
    end
end

ThreadTeams.shutdown! — Function
ThreadTeams.shutdown!()

Stop all worker tasks and drop the pool. Waits for a parallel region running in another task to finish first. The next parallel loop starts a new pool.

Throws an error when called from inside a parallel loop.
